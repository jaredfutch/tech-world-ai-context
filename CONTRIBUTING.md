# Contributing

Thanks for helping improve the Tech-World AI Context Framework.

## Good contributions

Useful contributions include:

- clearer or safer context-precedence rules;
- better `AGENTS.md` patterns;
- interoperability improvements across AI tools;
- sanitized examples;
- validation and test improvements;
- documentation corrections;
- privacy and security hardening;
- reproducible reports of framework behavior.

## Before opening a pull request

1. Search existing issues and pull requests for duplicates.
2. Keep examples sanitized. Do not include credentials, customer data, contracts, private correspondence, personal schedules, financial account data, or proprietary client/project details.
3. Explain what problem the change solves.
4. Distinguish mandatory specification behavior from optional recommendations.
5. Update documentation and tests/validation when behavior changes.
6. Add a changelog entry for release-worthy changes.

## Pull request expectations

A strong pull request includes:

- concise problem statement;
- proposed behavior;
- compatibility impact;
- privacy/security impact;
- files changed;
- verification performed;
- unresolved limitations.

For specification changes, state whether the proposal is patch-, minor-, or major-version material and why.

## Style

Prefer direct, testable language. Use MUST / MUST NOT only for mandatory compatibility requirements in the formal specification. Use SHOULD for strong recommendations and MAY for optional behavior.

Do not describe unverified behavior as guaranteed.
